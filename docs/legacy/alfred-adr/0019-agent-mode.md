# 0019. Agent mode: a persistent model session, typed tools, and a gate in code

Status: accepted as an owner-only pilot (owner decision, 2026-11-19). The dialogue manager stays the default and the fallback.

## Context
The dialogue manager (ADR 0006, 0014, 0017) fixes slot loops with rules, but every new wording needs new rules, and the model only classifies. The owner wants to try a conversational agent without giving up the preview and confirm gates.

## Decisions
1. **Switch**: `ALFRED_NL=agent` with `ALFRED_NL_CONSENT=1` turns the pilot on; the one-shot chain (`claude`, Qwen, rules) stays behind it as the manager's model. Rollback: change the value back to `claude` (or `off`) and restart, or send `/ajan kapat` (instant, no restart; `/ajan ac` and `/ajan` for status). `ALFRED_NL=readonly` answers reads only.
2. **Session** (`agent.py`): one persistent `claude -p --resume <uuid>` session for the owner chat; id, prompt version, turn count and last use live in `agent_sessions`. A new session starts after `ALFRED_AGENT_MAX_TURNS` (40) turns, 6 hours idle, a failed turn, or a changed prompt (the prompt version is a hash of the system prompt and the tool specs, so it is part of the session key). Facts survive rotation because they live in the DB (notes, lists, tasks, the draft); the first turn of a new session also carries the last messages.
3. **Lock-down**: `--tools "" --strict-mcp-config --mcp-config <json> --allowedTools mcp__alfred --permission-mode dontAsk --setting-sources "" --disable-slash-commands`, an empty dedicated cwd (`~/.config/alfred/agent-cwd`, `ALFRED_AGENT_CWD`), the environment scrubbed of Telegram, token, secret and Google variables, auto memory and CLAUDE.md loading disabled. `--no-session-persistence` is NOT used because resume needs the transcript. **Retention**: Claude Code keeps the transcript under `~/.claude/projects/<cwd slug>/` for `cleanupPeriodDays` (default 30); the owner may set a shorter period (for example 7) in his user settings; Alfred does not delete transcripts.
4. **Tools** (`agent_tools.py`, 19, typed, none takes a chat id): `calendar_range`, `find_events`, `propose_add_event`, `propose_edit_event`, `propose_delete_event`, `show_draft`, `edit_draft`, `commit_draft`, `list_get`, `list_add`, `list_check`, `list_remove`, `task_add`, `task_set_due`, `task_list`, `task_done`, `note_set`, `note_get`, `recent_messages`. They reach the model only as a stdlib MCP stdio server (`mcp_server.py`) that holds no data: it forwards over a private unix socket (`agent_bridge.py`, 0700 directory, 0600 socket, per-turn secret) to the bot process, which owns the calendar, the store and the owner binding.
5. **Drafts**: every write tool only creates or changes a DRAFT, which is an ordinary pending action (ADR 0004) with its version (the pending id); a second add extends the add draft, an edit creates a new version. Lists, tasks and notes are written immediately (Alfred's own store), but removing list items is a draft. Previews are rendered by code (`Assistant.render_pending`), never by the model, and are sent LAST in a reply.
6. **Grant gate**: `commit_draft` works only for a single-use grant that CODE minted (`AgentMode.mint_grant`) for the exact current version, when (a) the owner's latest message is a pure affirmative (`dialogue.parse_confirm`; deletions need `evet sil`, `sil` or an approval, a plain yes gets the hint and the preview again), and (b) the last bot message of the log contains the code-rendered preview of that same version. Any edit (a new version), any other bot message (digest, reminder), expiry, or the end of the turn kills it. "evet ama ..." never qualifies. The model's words about saving are never trusted: a first-person claim (`kaydettim`, `ekledim`, ...) without a real write in the turn is replaced, and when a grant was minted but the model forgot to commit, code commits (the owner's yes is honoured); a receipt is always the code text. Pure negatives cancel in code. The health menu is inserted before the preview in agent mode so it does not kill the grant.
7. **Context** built by code each turn (`AgentMode.context`): date, time, weekday, the next 7 days of events with ids, open lists, open tasks, notes, the open draft; plus the system line `[SİSTEM bugün=... saat=... hitap=... taslak=vN onay=EVET|YOK]`.
8. **Fallback chain**: agent -> dialogue manager (rules plus one-shot) -> read-only mode (`readonly_mode`: "şu an yazamıyorum", reads only). A failed turn (error, timeout, init event whose tools are not exactly the 19 expected ones) falls back for that message; three consecutive failures open a circuit breaker for 10 minutes; `ALFRED_AGENT_DAILY_CAP` (80) model calls a day. Debounce, buttons (Kaydet, Düzenle, İptal run the manager's `callback` path), message log, health monitor, voice and the watchdog are unchanged.
9. **Mid-draft flips** lose and duplicate nothing: both modes operate on the same pending action, and `claim_pending` is atomic (tested both directions).
10. **Self-test** at startup (`agent.self_test`, no model call): exact tool set, no chat parameter, commit refused without a grant, a compound yes mints nothing, a plain yes does, an edit kills the grant. A failure disables agent mode. The first real turn verifies the init event of the session.
11. **Privacy**: with agent mode on, the owner's messages and the next 7 days of event titles, lists, tasks and notes go to the model provider (the same consent as ADR 0004).

## Consequences
- New tables `agent_sessions`, `agent_notes`, `agent_grants` (idempotent; an existing database is backed up to `<db>.pre-agent.bak` first). Schema version 3.
- A message of the owner costs one model process start (about 5-10 s); the manager's rules stay as the instant path when agent mode is off.
- `scripts/agent_smoke.py` (3 real calls) verified the lock-down and the gate against the real CLI.
