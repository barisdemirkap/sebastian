# 0017. Purchase wordings go to the list; utterances about an existing event edit it

Status: accepted (owner decision, 2026-11-19).

## Context
Incident H (06:27): "ekmek alinacak domates alinacak" (bread to be bought, tomatoes to be bought) was read as an event and the bot asked "Hangi gün?" with a day menu. It belongs on the Alınacaklar list.
Incident I (06:27): the calendar already had "Aile hekimi: sağlık raporu al" today 09:00-10:00. The owner wrote that the doctor appointment is exactly at 8:50 and that they must be ready at 8:10 to leave. The bot proposed a NEW 60 minute event "Doktor randevusu için hazır ol 08:10-09:10" with a conflict warning against the doctor event: a duplicate-ish event that read the message the wrong way.

## Decisions
1. **Purchase classifier before the event path** (`purchase.classify`, pure, runs first in `Assistant._new`; the model never sees these). Wordings: `X alınacak`, `X alınacak Y alınacak` (the verb repeats), `X lazım`, `X almamız/almam lazım`, `X al`, `X bitti / kalmadı / tükendi` (ran out), `listeye X`, `X'i unutma`, `market: X, Y`, `eve X lazım`; items split on commas, `ve`, repeated verbs and newlines; quantities are kept (`2 litre süt`). The text must END in the verb, and calendar verbs (ekle, sil, ertele, hatırlat) never qualify. List adds are immediate (ADR 0016) and show the ☐/✔ view.
2. **Not list items**: appointment words (`i18n.APPOINTMENT_STEMS`: randevu, toplantı, doktor, muayene, ...), rapor/bilet/vize/ehliyet, task-like phrases (`gitmem lazım`, `yapacağım`, infinitives other than ekmek, mercimek, kaymak, yemek, kepek). `X bitti` stays a finished chore when X is a chore word, an open task or a nearby event (ADR 0013 keeps `çamaşır bitti`).
3. **Unclear: ONE numbered choice.** A purchase wording with a day, date or clock time (`yarın ekmek alınacak`) is both a list item and a possible calendar chore. The day/time words are dropped from the item and the bot asks `1) Alınacaklar listesine: ...  2) Takvime etkinlik olarak: ...` (state `awaiting: purchase`, which satisfies I10). 1 adds to the list immediately; 2 runs the old event path on the original words.
4. **Existing event first** (`readytime.py` pure, `Assistant._reschedule`, runs after the purchase classifier): a text with clock times that has a ready-by cue (`hazır olalım`, `hatırlat`) or a retime cue (`oldu`, `alındı`, `kaldı`) and names the subject of ONE upcoming timed event (fuzzy title match plus the synonym groups `i18n.SUBJECT_GROUPS`, e.g. doktor ~ hekim; the named day, else today and the next 7 days) is an EDIT/REMINDER candidate, never an add. Bare clock times take the reading (am/pm) closest to the event. One edit preview with before/after: start moved to the stated appointment time (duration kept), reminder lead = appointment time minus ready time (08:50 - 08:10 = 40 min). No separate "hazır ol" event is ever created for a mere reminder. Only a ready time: reminder lead = event start minus ready time. Examples covered: doctor, diş hekimi, toplantı, araç muayenesi, çamaşır.
5. **"X'de evden çıkmak için Y'de hazır olalım"**: the appointment time is X and ready-by is Y when X directly follows or precedes the word `randevu` (`randevusu tam 8.50de`). Otherwise it is ambiguous and ONE message shows both readings (`1) Randevu 08:50 olsun, hazır olma saati 08:10  2) Evden çıkış 08:50, randevu 09:00 olarak kalsın`; state `awaiting: reading`). The pick becomes the usual edit preview (reading 2 keeps the start, sets the reminder to event start minus ready time and adds the note `Evden çıkış: 08:50`); the write still needs the owner's yes (ADR 0002/0006).
6. **No conflict against itself**: the edit preview never warns about the event being edited (it already filtered it; now covered by incident fixtures).

## Consequences
Wrong guesses cost one visible choice. Fixtures: `2026-11-purchase-*`, `2026-11-event-like-words-are-not-list-items`, `2026-11-ready-time-*`. The existing-event step is deliberately narrow (a ready or retime cue plus a clock time) so ordinary adds (`yarın 15:00 diş hekimi`) are untouched; when several events share the subject the old flow runs.
